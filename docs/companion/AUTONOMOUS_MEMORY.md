# Opt-in semantic memory foundation

AutonomousMemoryService is storage-independent and uses CompanionDocumentStore in a new autonomous-memory namespace. It does not replace the existing semantic tables, conversation repositories or knowledge files. The SQLite adapter is optional; with persistence disabled, status accurately reports durableMemory=false. PostgreSQL/pgvector remain unselected/optional future adapters pending deployed-environment verification; no migration, embedding-model change or destructive operation was performed.

The existing MemoryJobService hooks successful conversation processing into AutonomousMemoryPipeline only when jarvis.memory.autonomous.enabled=true (default false). Otherwise legacy behavior and flags remain unchanged. A bounded 64-job queue and one low-priority worker use the configured AIProvider/model through the existing gateway. Jobs never block voice/conversation completion and are not automatically replayed after restart. Relevance is evaluated by the model's structured semantic extraction, not by remember keywords. The pipeline accepts at most 8 bounded, source-linked candidates per result and fails closed on malformed/uncertain output. Every retained fact has source conversation/request/time, server timestamps, confidence, category and optional expiration.

Credential/contact/identifier patterns are privacy deny guards, not a relevance algorithm. The structured classifier must explicitly report NON_SENSITIVE, STORE and sufficient finite confidence. Sensitive/credential/unknown classifications are refused; unsafe candidate text is rejected. Raw extraction prompts/responses are not added to the memory audit, and PrivateInferenceContext suppresses optional full outbound-prompt tracing for extraction without changing the global diagnostic setting. These safeguards are not a claim of perfect semantic DLP; extraction is opt-in and should be reviewed with the configured model before production use.

Canonical subject/predicate/value representations support duplicate detection; duplicate facts retain their ID and merge bounded source references. A changed value for the same canonical attribute does not overwrite a confirmed fact: the original becomes CONFLICT and the candidate PENDING_REVIEW. An explicit revision-checked user update resolves the attribute and supersedes other variants. This first stage does not implement vector semantic search or automatic conversation-prompt retrieval from these new records. It is a storage/extraction foundation, not a replacement for existing retrieval.

GET /api/v1/memory/autonomous lists owned non-expired records, including review/superseded states; only ACTIVE records should ever be treated as accepted facts. GET /status reports extraction/storage capability. PUT /{id} with expectedRevision/content performs explicit user resolution. DELETE /{id} deletes all related variants and stores content-free canonical fact tombstones plus a source-time cutoff, preventing queued old jobs and idle consolidation from recreating deleted information. Automatic restore is deliberately absent; a future explicit restore operation is needed to clear that choice.

Dreaming is separately opt-in (jarvis.memory.dreaming.enabled=false). After the configured idle interval, and only with no active inference and an idle extraction queue, it uses that same low-priority worker to expire temporary facts, merge actual canonical duplicates, and flag imported contradictory active variants for review. It never changes model weights or silently picks a winner. Audit entries contain operation/count/time only and are bounded to 200 per owner. This initial idle consolidation does not reprocess raw conversation archives or generate project summaries.

Tests cover keyword-free semantic extraction, duplicate/source merging, contradiction preservation and explicit updates, owner isolation, malformed/sensitive/credential screening, deletion tombstones, expiration, duplicate consolidation and opt-in/idle/inference-resource gates. New model/provider configuration is in config/companion-stage3.example.yml and is not loaded automatically.
